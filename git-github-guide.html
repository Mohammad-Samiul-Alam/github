1. Check and change your Git email

GitHub links commits to you by email. Check it before your first commit.

Check the current email

# this repository only
git config user.email
# all repositories on this computer
git config --global user.email
# see everything and where each value comes from
git config --list --show-origin

Change the email

# this repository only
git config user.email "your-new-email@example.com"
# all repositories (default)
git config --global user.email "your-new-email@example.com"
# also set your name
git config --global user.name "Your Name"
Added: keep your email privateOn GitHub, go to Settings → Emails and tick "Keep my email addresses private". Then use the ID+username@users.noreply.github.com address shown there.
Good to knowChanging the email only affects future commits. Commits you already made keep the old email.

2. Branches

Work on a feature without touching main.

# list branches (* marks the current one)
git branch
# create and switch to a new branch
git checkout -b feature
# modern equivalent
git switch -c feature
# go back to main
git checkout main

Added: rename the default branch to main

Older Git versions create master on git init. Your push command uses main, so rename it after the first commit:

git branch -M main

Added: merge a feature branch

git push -u origin feature
gh pr create --fill     # open a pull request
gh pr merge --merge     # or merge it on github.com

3. Upload a new project to GitHub

Run these in your project folder. Choose the route you prefer.

Corrected orderSet your email before the first commit, otherwise that commit carries the wrong address.
gh auth login
git init
git config user.email "your-new-email@example.com"
git add .
git commit -m "first commit"
git branch -M main
gh repo create my-awesome-project --public --source=. --remote=origin --push

Use --private instead of --public for a private repository. --push uploads for you, so the separate push step is not needed.

Correctedgh repo new is not a command. The right one is gh repo create. Also, -p means --template, not public. Use the full --public flag.

Create an empty repository on github.com first (no README), then:

gh auth login
git init
git config user.email "your-new-email@example.com"
git add .
git commit -m "first commit"
git branch -M main
git remote add origin https://github.com/your-username/repo-name.git
git push -u origin main

Check that the remote is set correctly:

git remote -v
Added: create a .gitignore firstBefore git add ., list files you never want online (secrets, dependencies, build output), for example:
.env
node_modules/
__pycache__/
.DS_Store

4. Update an existing repository

First time only: connect the folder to the repository

gh auth login
git init                  # skip if the folder is already a git repo
git remote add origin https://github.com/yourusername/your-repo.git
git remote -v             # verify
AddedIf you get "remote origin already exists", change it instead: git remote set-url origin <url>. If you started with gh repo clone, this step is not needed.

Normal update (recommended)

Adds, edits and deletions in your folder all go online. Nothing on GitHub is overwritten.

git add .
git commit -m "Describe what changed"
git pull --rebase origin main   # bring in anyone else's changes first
git push -u origin main

Force update (your folder replaces GitHub)

Use this only when you want GitHub to match your local copy exactly, discarding commits that exist only online.

git add .
git commit -m "Replace remote with local version"
git push --force-with-lease origin main
CorrectedPlain --force can erase a teammate's work without checking. --force-with-lease does the same job but refuses if the remote has commits you have not seen. Also, files you deleted locally are removed online by a normal push as well, once you commit the deletion.
Never force-pushto a shared branch your team uses, unless everyone has agreed.

5. Resolving a merge conflict

Your notes put push before add and commit. The working order is below.

git pull --rebase origin main
# Git stops and marks conflicts in the files:
# <<<<<<< yours   =======   theirs >>>>>>>
# edit each file, keep what you want, delete the markers
git add .
git rebase --continue
git push -u origin main
Added: bail out safelygit rebase --abort returns you to the state before the pull. After a plain git pull (merge) conflict, finish with git add . then git commit -m "Merge conflict resolved".

6. Everyday extras

CommandWhat it does
git statusShows changed, staged and untracked files
git diffShows unstaged changes line by line
git log --oneline --graphCompact commit history
git restore <file>Discards changes to a file (cannot be undone)
git restore --staged <file>Unstages a file but keeps your edits
git commit --amendFixes the last commit message or adds forgotten files (before pushing)
git stash / git stash popParks unfinished work, then brings it back
git pull origin mainDownloads and merges the latest online changes
gh repo clone user/repoDownloads a repository to your computer
gh auth statusChecks you are logged in
gh repo view --webOpens the repository in your browser
